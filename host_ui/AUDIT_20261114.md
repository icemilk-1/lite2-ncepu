## 0. 结论摘要（先看这 8 条）

1. **架构骨架是合格的**：三层速度链（主机安全闸门 → 传输层看门狗 → 机载执行门禁）+ 远端 0.3 s 零 Twist 兜底，急停/限速/状态超时/遥控接管/前倾保护都有实现，69 项单测全绿。
2. **但实机现在根本动不了**：机载执行门禁 `execution.reason = "disarmed"`，而**上位机没有任何"使能/解除"入口**；机载 `/airace/prepare`、`/airace/disarm` 服务只在 `run_lite2_trial.py` 里被调用，UI 侧完全没有对接（`grep prepare|disarm|arm` 在 host_ui 只有测试里出现）。这是第一优先级的功能缺失，不是 bug。
3. **使能还依赖一个没人发布的心跳**：`execution_guard` 要求 `/airace/depth_received` 新鲜，但该话题只有 `lite2_live.py` 的试跑进程会发（`lite2_live.py:390`），SSH 流不发布 → 即使今天加上使能按钮也会因 `stale_depth` 失败。
4. **安全上有 4 个 P0 级缺口**：① 全部 REST/WS 无鉴权、WS 不校验 Origin（任意网页可跨站接管机器狗、解急停）；② 导航不受操作者心跳约束，浏览器全关仍会自主跑；③ 进程被 kill 后厂商 UDP 侧零速无保证（未实测）；④ 姿态切换走独立 UDP 直发，绕过 SafetyCore，急停不能中止已开始的起立/趴下。
5. **刚抓到的实机证据**：SSH 链路在运行 495 s 后断开（`Socket exception: 10054`），**103 s 后仍未自动重连**，`/api/sensors` 全部过期、UI 只剩旧位姿，必须人工点"连接"才能恢复。断线自动重连是实机调试的刚性需求。
6. **地图页有一个必现场景的显示 bug**：地图在"传感器"工作区加载时画布是隐藏的（1×1），`fit()` 把缩放钳到最小值 2.5 px/m；切到"导航操控"后不重新适配，9.7×9.5 m 的真实地图只剩约 24 px。CDP 实测 `mapView.scale = 2.5`（正常应 ≈ 35–40）。
7. **相较宇树 App，我们缺的不是娱乐功能，而是"安全兜底 + 状态可见 + 运维闭环"**：电量/温度/故障码、控制权独占、断线重连、使能/解除、固件版本、标定/组网入口、录包回放。宇树把这些放在 App/机器人本体两侧，我们只能在上位机侧自己补齐。
8. **部署资料为零**：`host_ui/` 下没有 README、没有 requirements、没有启动脚本，根 README 也没提到上位机；SSH 口令靠环境变量 `HOST_UI_SSH_PASSWORD`，配置不持久化，机器人时钟是 2018 年（相机时间戳 1517160615）。这些是"第一次上现场"就会卡住的必需项。

### 1.1 四层安全矩阵（现有实现）

| 层 | 机制 | 位置 | 评价 |
|---|---|---|---|
| L1 上位机安全核心 | 急停锁存 → 状态超时 → 断链 → 模式未就绪 → 遥控接管(0.5 s 保持) → deadman → 手动/导航仲裁 → 硬限幅 → 按 dt 加速度限制 | `app/state.py:126-275` | 优先级设计正确，但 nav 无操作者心跳、姿态不受管、无 error_state/倾角门禁 |
| L2 传输层看门狗 | UDP 0.3 s→5 Hz 补零；ROS1 同构；SSH 宿主线程 0.3 s 改发 0 | `vendor_udp.py:370-401`、`ros1.py:572-596`、`ssh_ros.py:83-88` | 进程内有效；进程崩溃/OS 卡死无兜底 |
| L3 机载执行门禁 | armed/mode_confirmed/depth 心跳/state/feedback/指令新鲜/basic/error_state/摇杆/倾角 | `lite2_sim/hardware/execution_guard.py` | 最严格的一层，但上游 UI 不触发 prepare，等于常年关闭 |
| L4 远端兜底 | 0.3 s 无指令零 Twist；退出 finally 补零 | `ssh_ros_stream.py:104-122` | 断 SSH/断网时可靠（代码可证），已实机验证帧率 47–50 Hz |

## 4. 缺失的"必要性"（按优先级）

### P0-A 实机无法运动（功能闭环缺失）

1. **使能/解除入口**
   - 现状：机载 `lite2_live.py:122-123` 提供 `/airace/prepare`、`/airace/disarm`（srv Trigger），`execution.reason=disarmed` 拦截一切速度；host_ui 后端/前端零调用。
   - 必须：在"导航操控"页增加 `使能（上电进入自动模式）` / `解除（回手动站立）`，带前置检查与二次确认，状态实时回显 `armed/mode_confirmed/automatic_ack`。
   - 实现路径：`ssh_ros_stream.py` 增加 stdin 指令 → `rospy.ServiceProxy('/airace/prepare', Trigger)` / `('/airace/disarm', Trigger)`；`ssh_ros.py` 增加 `arm()/disarm()`；`server.py` 暴露 `/api/arm`；前端按钮 + 门禁状态卡片。
2. **深度心跳缺失导致永远无法使能**
   - `execution_guard.guarded_velocity` 要求 `/airace/depth_received` 新鲜（0.5 s），但全仓库只有 `lite2_live.py:390`（试跑进程）发布；实测 `control.depth_time=0`。
   - 必须：由 `ssh_ros_stream.py` 在收到新鲜深度图像时发布该心跳（它本来就在订深度），或提供独立 watchdog 节点；同时在 UI 显示"深度心跳有效/失效"，与使能按钮联动。
3. **姿态切换与使能/解除机制不统一**
   - 现状：主机 `ssh_ros.py:137-169` 直接向厂商 43893 发 `0x21040001`+`0x21010202`；机载 prepare 用 `0x21010D06`+`0x21010C03`、disarm 用 `0x21010C02`+`0x21010D05`。两套 mode 包语义未互相验证，姿态实机测试失败。
   - 必须：姿态/使能统一由机载服务执行（host 只发意图），UI 显示 basic 反馈与超时原因；实机逐项验收。
4. **只显示 `disarmed` 英文原因，操作者不知道如何恢复**
   - `app.js:439-441` 直接显示后端 `execution.reason`；需映射中文（disarmed=未使能、stale_depth=深度心跳失效、remote_takeover=遥控接管、motion_mode_not_ready=未站立…）并给出下一步动作。

### P0-B 安全（会伤人/失控）

5. **REST/WS 无鉴权、WS 不校验 Origin**：任意网页可跨站连 `ws://127.0.0.1:8710/ws` 下发电机指令或复位急停；`/api/link` 还能指定任意 IP/端口。建议：启动生成一次性 token（URL/首屏注入）、WS 校验 Origin 白名单、REST Header 校验、link options 白名单。改动约 250–350 行。
6. **导航无操作者心跳**：客户端全关后 A*/纯追踪仍继续跑；`clients` 仅用于展示。建议：nav 激活要求 `clients>0` 且 1 s 内有任意操作者心跳，否则取消导航 + 零速 + 事件。约 50–80 行。
7. **姿态切换绕过 SafetyCore**：`/api/posture` 只在开始前查急停，起立/趴下 300 ms–8 s 期间急停不能中止；直发 UDP 也不受限速/看门狗管。建议：姿态纳入安全核心（可中断、急停即取消、事件留痕），并把 host 姿态改走机载服务。
8. **急停闭环不完整**：前端 `wsSend` 不检查返回值（断线时仍提示"已触发"），后端复位无门槛（任意客户端瞬间复位），复位后若仍按着方向键会立刻再动。建议：ack 校验 + 发送失败红色报警 + 后端 hold/状态门槛 + 复位清键。
9. **进程崩溃后的零速无保证**：厂商 UDP 看门狗是进程内线程；USB/网络断开的实测未做。建议：`taskkill /F` 实测停稳时间并记录；不达标就在机载增加超时停车（厂商控制器支持性需核验）。这是**部署前必须完成的实机测试**，不是代码能替代的。
10. **控制权独占缺失**：当前 2 客户端，任意端可抢控；切换工作区甚至会主动发 `stop`。建议：操作权申请/接管/释放 + 接管互斥提示 + 掉线自动释放。
