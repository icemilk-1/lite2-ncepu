# “废墟智援”备赛执行计划

更新：2026年11月6日。适用赛题：第二届北京市大学生“人工智能+”创新大赛——具身智能机器人废墟灾害应急探测与救援。

## 1. 当前情况与必须先做的事

- 企业赛：按负责人提供的2026年11月26日倒排，距离今天20天。市教委公布的企业赛总体窗口为11月26日至12月5日，本赛题具体日期仍以赛题通知为准。
- 北京市线下决赛：官方通知为2026年12月26日，地点为北京工业大学奥林匹克体育馆；需经过校内推荐和企业选拔晋级。
- 负责人每周实习4—5天；工作日晚间每天约2小时，周末两天约10小时。本计划先按周末合计10小时、每周总投入约20小时估算。
- 实验室可能有机器狗，但品牌、型号、传感器、开发权限、现成代码均未确认；队伍人数与能力也未确认。
- 第一优先级：今天联系校内竞赛联络人，核查报名、队员、指导教师与校赛要求。官方通知要求11月7日前完成初始报名，提交后赛题、成员、教师及其排列顺序不得变更。不要为了凑人数随意填报尚未承诺投入的人。

本计划是执行建议，内部验收指标不是赛事评分标准。评分权重、方向选择和实操要求取得赛题组明确答复后再更新。

## 2. 已确认的规则与待澄清内容

### 已确认

1. 北京地区普通高校在校本科生参赛；每队3—5名学生。市教委总体通知要求指导教师1—2名；每人仅可参与一队，每队仅限一个赛题。
2. 校内预选推荐在企业选拔之前；总体通知要求高校11月25日前完成推荐，具体校内截止时间可能更早。赛题规定校内预选基于指定线上仿真平台开展，每校本赛题推荐不超过5队。
3. 企业赛核心任务包括运动控制与路径规划，以及生命目标的识别、定位、信息回传；最终成绩由实操和答辩加权形成，附件没有给出具体权重。
4. 允许商用四足机器人或仿真虚拟机器人，不限品牌；企业选拔又明确以现场实体或模型实操展示为主。因此，“允许仿真”不能直接解释为现场播放视频即可参赛。
5. 场地参考为12×10米，涉及坡道、S弯、死胡同分岔、乱石与限高隧道；其中过窄隧道需要识别并放弃通行。实际尺寸以后续资料为准。
6. 需提交研制报告、演示视频及实物图片、完整数字化仿真模型、源码、仿真测试报告、5分钟答辩PPT、知识产权说明。总体通知另要求签署并上传诚信与知识产权承诺书、安全承诺书。
7. 真机调试需要现场监护和隔离区域，不得改造高压或动力部件。外网API若需现场使用，应提前报备并完成联调核验。

### 今天向赛题组集中确认

- 正文的“两项核心任务”和附录的“两个方向”如何对应？是否可以分方向参赛，还是两项都必须完成？未答复前两项均保留基础功能。
- 实操与答辩分值、各赛段分值、超时/接管/碰撞/重试如何计分？是否允许人工初始化、人工重定位或遥控接管？
- 企业赛具体日期与地点、校内仿真入口和账号、模型包、场地配置表、目标定义、地面真值与评分工具在哪里获取？
- 目标是人员、人体模型、标志物还是其他对象？遮挡和弱光怎样设置？目标定位要求输出何种坐标、允许多大误差？
- 现场仿真演示是否可作为主方案？具体需要什么设备、运行方式与材料？录像只是备份还是允许作为部分评价依据？
- 报告模板、源码和模型提交方式、截止日期、知识产权材料模板、现场调试时长与网络要求是什么？
- “模型在线训练”是背景描述还是需要单独验收的任务？决赛是否新增任务或提高标准？

## 3. 负责人如何组织队伍

建议以4人为初始配置；如已具备第5名稳定成员，可专门承担测试和材料。报名人数及人选必须在提交前落实，不能假设赛后补人。

| 角色 | 主要责任 | 每次同步需给出的成果 |
| --- | --- | --- |
| 你：负责人、集成与验收 | 确定范围、接口、优先级，安排测试，统筹材料和5分钟答辩；只额外承担一个边界清楚的技术模块 | 本周可运行版本、主要阻塞及解决人、材料进度 |
| 本体与现场副负责人 | 确认借用和开发权限，运行官方示例，接通控制与传感器，负责工作日现场调试及设备安全 | 可复现启动步骤、传感器记录、真机演示视频 |
| 规划与仿真负责人 | 获取官方场景，完成路径、避障和死胡同恢复等任务，维护可运行仿真版本 | 固定场景下的运行记录、成功率和失败原因 |
| 感知识别负责人 | 根据官方目标定义完成检测、定位与回传，采集测试数据，评估弱光和误报 | 标注样本、检测与定位结果、指标统计 |
| 可选：测试与材料负责人 | 管理场景、数据、报告、视频、提交清单 | 测试记录和可提交材料包 |

现场副负责人必须能在你实习时独立启动系统、处理常规问题。缺少这个角色时，真机开发范围应主动收缩，并提前确认仿真展示方案的合规性。

管理规则：每个任务只有一名最终负责人，并写明截止日期和验收证据。队员工作日用“完成了什么／下一步／被什么卡住”三行更新；每周两次各20分钟同步。问题卡住超过24小时就上报，不等周末才集中暴露。

## 4. 前48小时设备盘点与决策

让现场副负责人到实验室，向老师或设备管理员逐项确认，不靠“应该有”排技术路线。

| 盘点项 | 要拿到的证据 |
| --- | --- |
| 本体型号和可用时间 | 铭牌照片、管理员确认、可预约时段、能否带离实验室参赛 |
| 二次开发能力 | SDK或开发文档、授权状态、当前可用示例、能否由程序控制行走与停止 |
| 传感器与计算设备 | 相机/深度相机/雷达/IMU/里程计的实际配置、数据样例、可用计算机 |
| 已有成果 | 学长或实验室现有代码、仿真模型、部署说明，以及可用于参赛和提交的权限 |
| 真机操作条件 | 急停方式、充电器和备用电池、现场监护人、调试空间 |

11月8日晚的内部验收：在有人监护的条件下，能按文档启动现有示例、程序控制基本行走与停止，并读到至少一种任务相关传感器数据；同时取得官方仿真入口并完成最基础运行。

11月9日决策：如果开发权限、官方示例或稳定现场人员仍没有落实，立即停止把所有进度押在真机接入上，集中完成官方仿真任务，向赛题组确认现场仿真展示方式。真机在解决阻塞后再接回，不等待到赛前一周才启动替代方案。

## 5. 企业赛前的技术范围

第一目标是完成“感知环境 → 规划行动 → 机器人通行 → 发现目标 → 定位回传 → 异常时停止或恢复”的可重复流程。官方基础场景、现有控制器和现成工程优先复用；机器人型号和权限确认后再选具体软件栈。

建议先实现：

- 利用已有稳定步态和官方示例控制机器人，逐段验证直行、转向、坡道、狭窄区域通行和退回。
- 用任务状态机组织场景任务，明确探索、通行、堵塞后退、重新规划、报告目标、完成或停止等状态。
- 根据实际传感器实现障碍感知、目标检测和定位；若只有单目相机，不把未经验证的像素位置称为准确世界坐标。定位手段要结合可用深度、地图和机器人位姿确定。
- 回传目标类别、置信度、图像、时间戳及在约定坐标系下的位置；界面以能核查结果为目标。
- 把过窄通道识别与放弃、任务恢复、弱光鲁棒性等赛题相关问题作为候选改进点，选一项重点验证。

前20天不安排从零训练步态、重做机器人底层控制、同时迁移多个仿真平台或堆叠大型新模型。这些工作若确属得分要求，应由已有经验的队员复用成熟方案；范围优先服从正式规则与团队能力。

## 7. 与实习并行的20小时预算

每周固定安排16小时，保留4小时缓冲；周末如实际是每天10小时，多出的时间优先用于休息、补测和突发故障，不立即增加新功能。

| 工作 | 每周预算 | 推荐安排 |
| --- | --- | --- |
| 真机与仿真联调、现场验收 | 8小时 | 周末分两块完成，由现场副负责人提前准备好设备与待测版本 |
| 你承担的一个技术模块 | 4小时 | 两个工作日晚间，每次2小时 |
| 组织、规则核查、接口与风险处理 | 2小时 | 分散在工作日，包含两次短同步 |
| 报告、数据说明、答辩 | 2小时 | 固定一个工作日晚间，每周累积 |
| 故障与临时事务缓冲 | 4小时 | 2小时工作日、2小时周末 |

工作日晚间每次只确定一个可交付成果。能离线做的代码审查、日志分析和材料整理放在晚上；需要设备的工作集中在提前预约的现场时段。尽早协调11月26日周四的请假与交通；12月26日为周六，仍需核实实习排班。若赛前确需工作日现场彩排，再按里程碑协调额外半天，不默认整月牺牲实习。

## 8. 验收与答辩如何准备

从第一次跑通开始保留实验记录，避免最后一周追补数据。

| 项目 | 记录方式 |
| --- | --- |
| 通行 | 固定路线和场地配置，记录成功次数/总次数、耗时、碰撞、接管、跌倒、失败位置 |
| 感知 | 固定测试目标和光照条件，记录漏检、误报、召回率；不要只展示挑选出的成功图片 |
| 定位与回传 | 明确坐标系和参考真值，记录位置误差、回传延迟与目标重复上报情况 |
| 鲁棒性 | 记录弱光、障碍变化、窄通道、死胡同场景的处理结果和恢复时间 |
| 改进点 | 用同一组条件比较基线和改进版本，说明改善了哪个问题，以及付出的代价 |

建议内部目标：11月22日前，在固定的代表性路线下试跑10次，争取至少8次完成预先约定任务，同时逐项展示正式规则要求的能力。这是内部稳定性目标，不能替代官方全场评分，也不能把未覆盖赛段算作完成。

5分钟答辩建议：问题与任务30秒；系统方案50秒；核心改进与演示90秒；测试结果与对照80秒；团队贡献和边界30秒；预留20秒。每项能力说明它用了什么输入、采取什么动作、效果如何测得、失败如何处理。现成平台与团队新增工作分别如实说明。

现场准备可启动的主方案、已确认允许的替代运行方式，以及清楚标注用途的演示录像。保留本地依赖、模型权重、代码和配置备份；录像不能默认为可替代实操。每项材料设置负责人，赛前逐项检查并保存提交回执。
