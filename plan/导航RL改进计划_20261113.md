# 导航 RL 改进计划

编制日期为 2026-11-13。目标是在现有速度级 MuJoCo 导航工程中接入学习式局部规划器，形成可重复训练、独立评测和完整课程验证的实验链路。

## 1. 当前依据与交付目标

当前局部规划器通过离散速度采样、短时轨迹预测和评分选择速度。RL 接入位置位于 `NavigationSession.tick()` 调用 `_local_rollout()` 的局部决策层。动作采用已有 `VelocityCommand(vx, ω)`，控制周期为 0.05 秒。

方案 B 已采用默认课程配置。种子 42、43、45 全部完成 7/7 段，0 碰撞、0 倒车指令，耗时分别为 333.5、328.75、347.75 秒。验收来源为 `lite2_sim/mujoco/course_acceptance.json`。这些记录提供速度级仿真基线，实机验证另需采集现场证据。

本轮交付包括以下内容。

- 可通过配置选择现有规划器或 RL 策略的局部控制入口。
- 支持重复 reset、固定种子和有界 episode 的 Gymnasium 环境。
- 固定版本的独立训练环境、PPO 训练与模型加载脚本。
- 独立评测报告，包含任务效果、安全拦截和推理开销。
- 完整课程复核记录、对比视频与结论。

## 2. 实施原则

1. 复用定位建图、全局 A*、课程状态机、命令合同和执行器。
2. 将任务状态判断、安全检查、速度候选生成建立清晰接口，允许两类策略使用一致的输入与评测条件。
3. 所有策略输入由可部署的估计状态和传感器观测生成。仿真真值可用于训练奖励与独立评分，使用位置需显式记录。
4. 训练依赖放入独立环境，验证其与当前 MuJoCo 及 NumPy 版本的兼容性。
5. 先以最小局部任务验证闭环与吞吐，再决定训练步数和场景规模。

## 3. 阶段一——整理局部策略接口

### 改动范围

- 在 `controllers/sensor_capture/navigation_core/session.py` 中建立局部策略调用入口，仅在允许正常行驶的任务状态执行策略推理。
- 保留观测过期、取消、任务完成、进度超时和恢复状态的控制优先级。
- 从 `_local_rollout()` 整理可复用的候选轨迹检查逻辑，覆盖矩形包络、已观测空间、地形支撑、台阶与地图边缘。
- 将策略候选动作、安全检查后的动作、执行端实际速度分别记录。
- 定义策略异常、非有限数、超时和无安全候选时的处理。输出有效期明确的停车命令，并记录触发原因。是否调用基线策略由显式配置控制，评测报告统计调用次数。

### 验收

- 使用基线策略运行已有回归与 3 个课程种子，检查任务结果和碰撞计数。
- 为策略接入新增针对性回归，覆盖无效动作、过期观测、取消与安全拒绝。
- 策略模型的加载与推理具有独立入口，可在训练环境之外调用。

## 4. 阶段二——构建可重复训练环境

### reset

`MujocoVelocityExecutor.set_pose()` 负责写入 MuJoCo 位姿。环境 reset 同时需要初始化执行器内部位姿、速度、地面高度、姿态、延迟队列、碰撞计数和随机数状态，以及传感器、定位器、地图、任务计时与路径状态。

优先缓存静态场景模型，每个并行环境维护独立的可变模型状态、`MjData` 与会话。动态障碍修改不得跨环境共享。第一版可重新构造会话和执行器，待测得 reset 开销后再优化。

### step

每步完成动作解码、状态检查、安全过滤、执行器推进、按频率更新观测、状态估计及奖励计算。控制频率为 20 Hz，雷达按已有 10 Hz 调度，并提供观测年龄。

- 成功到达或发生任务定义的失败时设置 `terminated`。
- 到达 episode 时间预算时设置 `truncated`。
- 碰撞失败采用 `executor.step()` 返回标志，覆盖几何碰撞与不可支撑地形。
- 训练模式关闭逐帧原始点云和大型 JSON 落盘，保留回合统计与抽样诊断。评测模式启用完整记录。

### 验收

- 通过 Gymnasium / SB3 环境检查器。
- 相同种子和动作序列得到相同轨迹与奖励，容差显式记录。
- 连续 reset 后计时、地图、延迟队列和任务状态回到规定初始状态。
- 并行环境之间的障碍修改与随机数状态互不影响。

## 5. 阶段三——确定观测、动作和奖励

### 观测初版

| 分量 | 初版设计 | 核验内容 |
|---|---|---|
| 局部地图 | 自车坐标系 3×3 m、0.1 m 分辨率，约 30×30 栅格 | 从现有 0.05 m 地图保守聚合，占据与危险区域避免平均后消失 |
| 地图通道 | 占据、未知、地形危险 | 区分无观测与可通行，保留包络检查需要的风险信息 |
| 雷达 | 全周 72 个扇区的障碍距离与有效性 | 采用经现有地形投影处理的观测，核验雷达至机身坐标变换 |
| 路径参考 | 局部参考点或短路径段的自车坐标 | 从在线 `session.plan.path` 读取，处理路径为空与重规划 |
| 运动状态 | 当前 `v、ω`、上一动作、观测年龄 | 所有量归一化，并记录量程 |

上述尺寸为起步设计，最终由观测可视化和吞吐结果确定。多通道地图可使用独立编码器，首轮同时评估展平 MLP 的计算成本。动态障碍阶段加入多帧观测或循环策略，并明确历史窗口与重置行为。

### 动作初版

使用二维连续归一化动作，经映射得到 `vx∈[0, 0.15] m/s`、`ω∈[-0.4, 0.4] rad/s`。上限由运行配置读取。训练与部署使用同一映射及安全过滤。

### 奖励初版

采用路径进度、成功奖励、碰撞惩罚、时间成本、归一化动作变化惩罚及安全干预惩罚。各项独立记录均值、累计值与分布，便于定位奖励失衡。

- 路径进度使用有界局部投影。重规划时重置参考，避免路径坐标跳变产生虚假奖励。
- 到达奖励每回合发放一次，碰撞按任务定义终止。
- 对回退再前进、原地转向、持续停车、反复请求危险动作等序列做奖励检查。
- 最小间距作为独立指标。若加入奖励，需同时明确几何间距与观测间距的来源。

### 验收

抽取现有运行数据和在线 episode，输出观测预览，检查坐标方向、地图未知区域、雷达无回波和路径参考。记录奖励分项，确认通过前述动作序列检查。

## 6. 阶段四——采样基准与 PPO 最小实验

### 吞吐测试

测试单环境及 2、4 个并行环境，记录以下数据。

- 总采样 step/s、reset 平均及 P95 耗时。
- 雷达、地图更新、安全过滤、执行器和策略推理耗时。
- CPU 使用、内存占用与日志体积。
- 对 10 万、50 万、100 万步的墙钟时间估计，训练更新耗时单独计入。

### 场景顺序

1. 平地短路径跟踪，检查动作映射与成功奖励。
2. 单障碍绕行，随机化起点、目标和障碍位置。
3. `obstacle_bypass` 局部任务，加入静态布局扰动与观测噪声。
4. 移动障碍任务，新增轨迹、速度和出现时刻采样。现有定时插入/移除场景作为单独测试。

每个场景配置独立的可达性检查与时间预算。`obstacle_bypass` 现有段预算为 150 秒，episode 上限依据可达路线长度和实测耗时确定。

### 训练安排

先用 CPU 版 SB3 PPO 与固定种子完成短训练和模型重载，验证奖励、评估及 checkpoint 链路。根据吞吐确定正式步数。训练种子至少 3 个，保存依赖版本、配置、源码哈希、模型、归一化统计和动作映射。

### 阶段决策

若最小跟踪任务仍无法学习，先检查观测、奖励与终止逻辑。若吞吐无法支持可用预算，优先依据耗时分解优化训练路径，并明确简化环境与原环境的验证差异。训练时长与收敛效果在基准完成后给出估计。

## 7. 阶段五——独立评测与完整课程复核

固定一组独立测试配置与至少 30 个评测种子，训练调参阶段使用另一组验证配置。对 3 个训练种子的模型分别评测，报告模型间差异。基线与 RL 使用相同起点、障碍、传感器扰动、速度上限、任务预算和执行器设置。

| 指标 | 记录方式 |
|---|---|
| 成功率 | 成功数 / 总回合数，附区间估计 |
| 耗时与路径长度 | 报告成功回合统计，同时列出失败和超时数量 |
| 碰撞 | 包括执行器拦截计数及原因 |
| 最小间距 | 使用一致机身包络独立评分 |
| 安全干预 | 拒绝、动作修正、停车及基线接管次数 |
| 平滑性 | 归一化动作变化与实际速度变化 |
| 实时性 | 观测构造、安全过滤与策略推理的 P50 / P95 / 最大耗时 |
| 泛化 | 按静态绕障、移动障碍、噪声和响应扰动分别统计 |

拟采用以下候选晋级条件，后续可按比赛目标调整。

- 评测集成功率达到基线水平，并在耗时、路径长度或间距中至少一项呈现可重复改进。
- 碰撞和安全拦截结果均单独报告，能够解释成功来源。
- 完整控制周期满足 50 ms 预算，并记录超时处理结果。
- 完整课程种子 42、43、45 均完成 7/7 段、0 碰撞，记录倒车与恢复行为。

局部阶段优先仅在目标赛段启用 RL，再检验跨赛段使用。完整课程结果与局部独立评测同时交付。

## 8. 阶段六——部署准备

在目标机架构与软件版本明确后，选择可支持的推理运行时，核对导出模型、归一化与动作映射的一致性。对记录观测逐帧比较训练环境和部署环境的策略输出。

按 `hardware/README.md` 核验厂商速度接口、单位、运动模式、控制权、响应延迟与停车距离，完成传感器和坐标系适配。先进行只记录输出的影子运行，再依据现场授权和测试条件开展低速分段验证。

实机结果需要各自的运行记录。仿真验收中持续标注 `physical_gait_validated=false`，直到对应现场证据建立。

## 9. 预计工作量与完成条件

| 工作 | 初步人力估计 | 依赖 |
|---|---|---|
| 策略入口与安全检查整理 | 0.5–1 天 | 现有回归通过 |
| Gym 环境、reset 与观测编码 | 1–2 天 | 策略接口确定 |
| 吞吐基准与短训练闭环 | 0.5–1 天 | 环境检查通过 |
| 正式训练与奖励调整 | 按实测采样预算确定 | 最小任务学习有效 |
| 独立评测、课程复核与视频 | 1 天起 | 模型和测试配置冻结 |

这些估计基于首次接入工作量，实际进度随 reset、吞吐与训练结果更新。首个可评审里程碑为单 episode 闭环、重复 reset 检查和吞吐报告。

完成时交付代码、可复现命令、依赖版本、模型及归一化文件、评测 JSON/表格、视频和局限说明。若实验效果不足，保留实际结果并记录原因，结论依据独立测试给出。
