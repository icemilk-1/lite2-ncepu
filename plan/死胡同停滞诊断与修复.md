## 2. 根因（4 条，按影响排序）

### A. 控制器与局部 rollout 的视距不一致（0.25 m vs 0.45 m）
`control.py:40` 用 `lookahead_m=0.25` 算期望转向；`session._local_rollout` 原先固定用 `0.45` 算打分目标。掉头场景下两个目标点落在 ±π 两侧 → 控制器要“左转 +0.4”，rollout 却按“右转更近”打分（离线复现：`desired_heading≈-2.90 rad`，而 `preferred.angular=+0.4`）。两层相互抵消。

### B. 180° 掉头时线性化代价退化，(0,0) 成为全局最优
离线复现该 tick 的 20 个候选真实分数（`_local_rollout` 全量输出）：

| 候选 (v, ω) | 分数 |
|---|---|
| **(0.0, 0.0)** | **-1.531（最优）** |
| (0.0, +0.4) | -1.605 |
| (0.0, -0.4) | -1.723 |
| (0.03, +0.4) | -1.702 |
| (0.15, +0.4) | -1.720 |

原因：目标在机身**后方** → 任何前进都增大距离项；旋转会扫过墙边栅格 → `2*margin_cost` 惩罚；航向项权重仅 0.25。于是“站着不动”严格优于任何动作。

### C. 恢复层形同虚设
- `recovery_succeeded` 在恢复开始后 0.05 s 触发（下一 tick 导航器又回 `navigating`），attempts 被清零 → 永远只发 1 个 50 ms 脉冲；
- 恢复旋转固定向 `+0.6*max_yaw`（左转），与需要的转向不一定同号；
- `stalled` 既是 `RECOVERABLE_STATES` 的入口，又是 `TERMINAL_STATES` 成员，第二次触发直接终态。

### D. `forward_only` 语义过强
它是“**到达检查点时朝前**”的约束（`course._set_goal`），却被用于限制整段路径的可选速度；虽不禁止原地旋转，但在 B 的评分下进一步压缩了可行解空间。

## 3. 已实施的修复

| 位置 | 改动 |
|---|---|
| `navigation_core/session.py` `_local_rollout` | 消除双层视距打架：rollout 仍用长视距 `rollout_lookahead_m=0.45`（短视距会贴着坡道/管口内沿切角，实测在坡道内边缘楔死），但打分与“转向一致性”项改为基于**同一视距目标**的 `preferred_angular=clamp(2*desired_heading)`，不再混用控制器的 0.25 m 偏好 |
| 同上 | 新增“原地转向脱困”原语：当最优动作 \|v\|<0.05 且 \|期望航向误差\|>0.6 rad 时，改选“航向误差下降最多”的可行原地旋转（debug 字段 `standstill_escape`/`scores` 可观测） |
| `navigation_core/session.py` `tick` | recovery 独占其 2.5 s 窗口；只有真实位移 ≥ `progress_distance_m`(6 cm) 才 `recovery_succeeded`，否则按 attempts 重试（上限 3） |
| `navigation_core/session.py` `_recover` | 旋转方向由“固定左转”改为“朝规划目标方向”，并在重试时重置起点位姿 |
| `tests/test_navigation_session.py` | 新增 4 条回归：掉头不再发 (0,0)、forward_only 过滤、rollout 视距可配置且长于控制器视距、recovery 窗口不被下一 tick 取消 |

验证：`tools/run_tests.py` **110/110 通过**；离线复现该 tick 现在输出 `(0, +0.4)`（`standstill_escape=1`），不再恒为零。
