# 绝影 Lite2 部署准备

## 当前交付

共享内核处理占据地图、连续支撑面、A*、前沿探索、进度超时和有界卡死恢复。当前策略绕开检测到的物体，连续坡面仍可通行。仿真任务跳过圆管，将原碎石往返任务合并为一次自主绕障通行。

准备包包含 Python 3.6 语法兼容的共享内核、ROS1 Twist 执行适配器、离线回归测试、输入回放和只读环境采集工具。依赖版本由机载 Python 与平台共同确定，包内记录 NumPy 最低版本。机载环境兼容性通过下列离线测试确认。

```bash
python3 -m unittest discover -s tests -p test_navigation_core.py
python3 tools/collect_lite2_environment.py --output lite2_environment.json
```

环境采集工具执行 `rosversion`、`rostopic list`、`rosnode list`。可以重复传入 `--topic` 检查实际点云、IMU、里程计和速度话题的类型及发布者。

## 填写实机配置

将 `profile.example.json` 复制为实机配置，依据测量和接口查询填写空值。

| 配置 | 数据来源 |
|---|---|
| 系统、CPU 架构、Python、ROS | 环境采集报告 |
| 雷达型号、组织化点云维度、量程 | 实际驱动与点云消息 |
| 雷达及 IMU 外参、坐标轴方向 | 实机安装测量与 TF |
| 里程计速度、姿态、支撑高度与时间戳 | 厂商反馈或状态估计节点 |
| 机身尺寸和净空裕量 | 含载荷与传感器机构的实测外形 |
| 速度接口、模式反馈、单位、换算 | 当前固件对应的厂商接口 |
| 速度响应、停车距离、超时行为 | 实机分段测试记录 |

当前仿真使用 0.60 × 0.44 m 机身包络、0.15 m/s 速度上限和 0.4 rad/s 转速上限。这些值的来源为仿真假设，实机配置使用测量结果。

本地 DeepRobotDog 示例使用 UDP 整数指令，前进示例值为 `10000`。该值到 m/s 的对应关系需要按实际固件核对。共享 `VelocityCommand` 使用 m/s 和 rad/s。

## 传感器接入与录包

`NavigationObservation` 包含时间戳、坐标系、二维射线及地形元数据。`MotionObservation` 包含实测前进速度、偏航角速度、IMU 倾角和支撑高度。

组织化点云通过 `terrain.project_cloud` 做倾角补偿与地形投影。接入时核对点云层序、方位角序、雷达外参，以及支撑高度和点云高度使用的参考系。驱动输出的点云组织方式决定前处理适配。

在已确认的实际话题上录制点云、IMU、里程计、`/tf` 和 `/tf_static`，保留设备时间戳。先检查静止、直线、转向、平地与连续坡面的投影和定位结果，再回放含低矮物体的绕障数据。

共享会话的输入顺序为运动传播、观测更新、控制 tick。所有输入采用同一时间基准，记录输出命令与任务状态以便重复回放。

## 控制接入与验证记录

ROS1 适配器接受已核对的话题、速度限制、控制权状态和模式反馈函数。集成节点周期调用 `publish` 与独立的 `watchdog`，取消和退出时调用 `cancel`。厂商控制器侧的超时停车能力依据实际接口核验。

机载 `lite2_live.py bridge` 的执行门禁接受正负线速度，正值前进、负值后退，
当前硬限幅为 ±0.05 m/s，偏航角速度为 ±0.1 rad/s。
导航速度指令使用 V1.2.3 的 code 320 双精度浮点值，执行门禁保留其符号。
上位机的前进、后退按钮及键盘指令均经过相同的使能、模式、状态、深度和指令时效检查。
实际前后方向、速度响应及停车距离由现场低速测试记录确认。

验证记录应覆盖以下情形。

- 正向速度与偏航的坐标轴、单位和限幅。
- 模式未就绪、过期指令、未来时间戳和主动取消。
- 上层进程退出、网络中断、传感器失联及执行端失联。
- 零速度输出到实测停稳的时间、距离及反馈。
- 低矮障碍的地图保留、机身包络避让和卡死恢复。

仿真独立评分记录碰撞、低矮碎石平面包络重叠、终点误差、停车和任务完成事件。足端接触、步态稳定性、实机控制通道和实际传感器特性需要对应的现场验证记录。
